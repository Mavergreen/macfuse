# Ingredients

Everything baked into macFUSE for Mavericks, where it is pinned and what moves it.

| Ingredient | Pinned in | Tracked by | A bump |
|---|---|---|---|
| macFUSE | `UPSTREAM_VERSION` (bare upstream release; the tag is `macfuse-<version>`) | `github-releases` on `macfuse/macfuse`, `extractVersionTemplate` `^macfuse-(?<version>.+)$` | a new upstream release, `<version>-mavericks.1` |
| macFUSE source commits (Library-2, Library-3, Mount, Framework) | `components/macfuse-sources/pins` (a commit and its tarball's SHA-256 each) | they move with `UPSTREAM_VERSION`: the pins bot (`.github/workflows/pins-bot.yml`, `scripts/pin-sources.sh`) writes them on Renovate's branch from the release tag's gitlinks | the bumped release's commits |
| libfuse 2 `MAP_ANONYMOUS` workaround (per-repo back-fill): `libfuse/config/lib2/config.h` includes `<sys/mman.h>` and then undefines `MAP_ANONYMOUS`, because the pinned Recaulk's `sys/mman.h` defines it under `_POSIX_C_SOURCE` (as `MAP_ANON`, which the 10.9 SDK hides there), which would turn on `fuse.c`'s slab allocator that upstream's build leaves off | `libfuse/config/lib2/config.h` | `tests/libfuse-config-test.sh` probes the pinned Recaulk's header and fails once the workaround is no longer needed | exit: Recaulk's `sys/mman.h` fix (plan 1); then delete the two lines |
| macFUSE.framework 10.9 SDK declarations (per-repo back-fill): `framework/sdk109-prelude.h`, passed with `-include` to the framework and `tests/framework-fs` builds, declares what upstream's Framework sources use and the 10.9 SDK lacks: `NS_ASSUME_NONNULL_BEGIN`/`END` (10.11 SDK), `NS_SWIFT_NAME` (10.11), the `NSFileAttributeKey` (10.12) and `NSErrorUserInfoKey` (10.13) typedefs, `PREALLOCATE` (the 10.9 SDK has it only in `<sys/vnode.h>`, which newer SDKs reach through Foundation) and `RENAME_SWAP`/`RENAME_EXCL` (10.12's `<sys/stdio.h>`) | `framework/sdk109-prelude.h` | `build/build-framework.sh` fails to compile if a new upstream needs another | exit: a shared 10.9 SDK overlay (Recaulk headers or shipyard's SDK) that declares the newer-SDK Foundation annotations and typedefs; then delete the prelude |
| macFUSE.framework generic collections (per-repo back-fill): `build/build-framework.sh` compiles from copies of upstream's sources and headers with the type arguments of `NSArray`, `NSMutableArray`, `NSDictionary`, `NSMutableDictionary`, `NSSet` and `NSOrderedSet` removed (nested ones included), because the 10.9 SDK declares those classes without type parameters (lightweight generics came with the 10.11 SDK), so clang rejects `NSDictionary<NSString *, id> *`; compile-time only, the framework ships upstream's headers unchanged | `build/build-framework.sh` | `build/build-framework.sh` fails to compile if a new upstream uses another parameterized class | exit: the same shared 10.9 SDK overlay, declaring Foundation's collections with lightweight-generic type parameters; then compile upstream's files directly |
| Drydock (rewrites upstream's closed `mount_macfuse` and `load_macfuse` for 10.9: `build/adapt-helpers.sh`, recipes in `helpers/`) | `components/drydock/version` (a release tag, `vX.Y.Z`, read by shipyard's `fetch_drydock.sh`) and `components/drydock/linux-sha256` | `github-releases` on `Mavergreen/drydock` (the Linux digest by hand, see `.github/renovate.json`) | the bumped release's `drydock-macho-rewrite`; must pass `tests/helpers-recipe-test.sh` |

No upstream release notes beyond the link: `build/upstream-release-notes-url.sh` links `https://github.com/macfuse/macfuse/releases/tag/macfuse-<version>`.

## Conformance deviations

- native-build:closed-helpers: a native 10.9 build cannot read the upstream dmg (APFS), so it lacks the closed helpers that ship only in the dmg. Exit: shipyard QUEUE "A dmg/APFS reader that runs on 10.9 and Linux".
- objc-measure:macFUSE: the strict compat guard (build/compat-guard.sh, Drydock v0.5.0) cannot measure macFUSE.framework for Drydock gaps only: its `_objc_loadWeak` import (a block-captured `__weak` under manual reference counting) is unclassified (unclassified-objc-runtime-import); clang copies `objc_msgSend` between registers in `fusefm_destroy` and tail-calls through the copy, which the reader does not follow (indirect-objc-entry); and once those are fixed, its load of upstream's absolute install name `/usr/local/lib/libfuse.2.dylib` is not resolvable inside a shipped root (escaping-dependency; not reported today, so it has no row yet). It passes the default guard; tests/lib/strict-measure.sh requires exactly the findings and counts tests/lib/objc-measure.tsv lists for it, so a gap that closes or appears forces the rows to change. Exit: the Drydock fixes (classify `_objc_loadWeak`, follow entry-point register copies, map absolute install names into the shipped root) pinned by shipyard; then delete its rows and this entry.
- objc-measure:libfuse.2.dylib: the strict compat guard cannot measure libfuse 2 for one Drydock gap only: its load of upstream's absolute install name `/Library/Filesystems/macfuse.fs/Contents/Frameworks/MFMount.framework/Versions/A/MFMount` is not resolvable inside a shipped root (escaping-dependency). It passes the default guard; tests/lib/objc-measure.tsv lists the one excused finding. Exit: Drydock mapping absolute install names into the shipped root, pinned by shipyard; then delete its row and this entry.
- objc-measure:libfuse3.4.dylib: the same as libfuse.2.dylib, for libfuse 3's load of MFMount's absolute install name. Exit: the same.
- objc-measure:mount_macfuse: the strict compat guard measures none of upstream's closed `mount_macfuse`'s Objective-C sends (adapted by build/adapt-helpers.sh), its CF/AppKit alert path included, until Drydock's spilled-msgSend gap is fixed (queued with Drydock as gap 4): its compiler spills `objc_msgSend` to frame slots and reloads it from there (indirect-objc-entry, 157 findings in three forms), so the analyzer stops before measuring anything. The evidence for its sends is, for now, the release VM job's run of that alert path (Task 11). It passes the default guard apart from its declared sdk-pin; tests/lib/objc-measure.tsv lists the exact findings and counts. Exit: Drydock following an Objective-C entry point through frame-slot spills, pinned by shipyard; then delete its rows and this entry.
- sdk-pin:*/fs/Contents/Resources/mount_macfuse: upstream's closed binary records SDK 27.0; Drydock's target 10.9 keeps the recorded SDK by design and has no statement to change it
- sdk-pin:*/fs/Contents/Resources/load_macfuse: upstream's closed binary records SDK 27.0; Drydock's target 10.9 keeps the recorded SDK by design and has no statement to change it
