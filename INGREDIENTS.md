# Ingredients

Everything baked into macFUSE for Mavericks, where it is pinned and what moves it.

| Ingredient | Pinned in | Tracked by | A bump |
|---|---|---|---|
| macFUSE | `UPSTREAM_VERSION` (bare upstream release; the tag is `macfuse-<version>`) | `github-releases` on `macfuse/macfuse`, `extractVersionTemplate` `^macfuse-(?<version>.+)$` | a new upstream release, `<version>-mavericks.1`, once a person has refreshed the goldens (below) |
| macFUSE source commits (Library-2, Library-3, Mount, Framework) | `components/macfuse-sources/pins` (a commit and its tarball's SHA-256 each) | they move with `UPSTREAM_VERSION`: the pins bot (`.github/workflows/pins-bot.yml`, `scripts/pin-sources.sh`) writes them on Renovate's branch from the release tag's gitlinks | the bumped release's commits |
| macFUSE.framework 10.9 SDK declarations (per-repo back-fill): `framework/sdk109-prelude.h`, passed with `-include` to the framework and `tests/framework-fs` builds, declares what upstream's Framework sources use and the 10.9 SDK lacks: `NS_ASSUME_NONNULL_BEGIN`/`END` (10.11 SDK), `NS_SWIFT_NAME` (10.11), the `NSFileAttributeKey` (10.12) and `NSErrorUserInfoKey` (10.13) typedefs, `PREALLOCATE` (the 10.9 SDK has it only in `<sys/vnode.h>`, which newer SDKs reach through Foundation) and `RENAME_SWAP`/`RENAME_EXCL` (10.12's `<sys/stdio.h>`) | `framework/sdk109-prelude.h` | `build/build-framework.sh` fails to compile if a new upstream needs another | exit: a shared 10.9 SDK overlay (Recaulk headers or shipyard's SDK) that declares the newer-SDK Foundation annotations and typedefs; then delete the prelude |
| macFUSE.framework generic collections (per-repo back-fill): `build/build-framework.sh` compiles from copies of upstream's sources and headers with the type arguments of `NSArray`, `NSMutableArray`, `NSDictionary`, `NSMutableDictionary`, `NSSet` and `NSOrderedSet` removed (nested ones included), because the 10.9 SDK declares those classes without type parameters (lightweight generics came with the 10.11 SDK), so clang rejects `NSDictionary<NSString *, id> *`; compile-time only, the framework ships upstream's headers unchanged | `build/build-framework.sh` | `build/build-framework.sh` fails to compile if a new upstream uses another parameterized class | exit: the same shared 10.9 SDK overlay, declaring Foundation's collections with lightweight-generic type parameters; then compile upstream's files directly |
| Drydock (rewrites upstream's closed `mount_macfuse` and `load_macfuse` for 10.9: `build/adapt-helpers.sh`, recipes in `helpers/`; and the kext's vnode-op table, `vnodeop replace`, Drydock 0.6.0 or later: `build/retarget-kext.sh`, recipe `kext/macfuse.drydock`) | `components/drydock/version` (a release tag, `vX.Y.Z`, read by shipyard's `fetch_drydock.sh`) and `components/drydock/linux-sha256` | `github-releases` on `Mavergreen/drydock` (the Linux digest by hand, see `.github/renovate.json`) | the bumped release's `drydock-macho-rewrite`; must pass `tests/helpers-recipe-test.sh` and `tests/retarget-kext-test.sh` (the kext's golden sha256) |
| Updater icon and license notice: upstream's `macfuse.fs/Contents/Resources/macfuse.app/Contents/Resources/AppIcon.icns` (the updater's icon, `build/build-updater.sh`) and `macfuse.fs/Contents/Resources/License.rtf` (staged at the same place in `fs/` by `build/stage.sh`, the notice upstream's license asks a binary redistribution to carry), both read from the extracted dmg at build time, never committed | `UPSTREAM_VERSION` (the release's dmg) | they move with `UPSTREAM_VERSION` | the bumped release's icon and notice |
| clang22 (compiles MFMount, libfuse, macFUSE.framework, the osrelease shim and the updater; supplies the `llvm-*` Mach-O readers) | `components/clang22/version`, plus its Linux archive's line of that release's `SHA256SUMS` in `components/clang22/linux-sha256` (read only by a Linux host, which builds nothing here but the updater) | `github-releases` on `Mavergreen/clang-22`, `-mavericks.N` versioning (the Linux digest by hand) | a bump repackages: every binary we compile is rebuilt with it |
| Recaulk (`librecaulk.a`, linked whole into MFMount and through clang22's config into every compiled binary; `libRecaulkSystem.dylib`, which the adapted `mount_macfuse` loads; and its kernel back-fill kext, which the retargeted `macfuse.kext` links and `build/retarget-kext.sh` reads from the pkg's payload) | `components/recaulk/version` (a release tag, `YYYYMMDD.N`); the pkg's preinstall requires that Recaulk or newer | the shared preset's manager (`extends: github>Mavergreen/shipyard`): `github-releases` on `Mavergreen/recaulk`, date versioning; this repo adds none | a bump repackages and raises the Recaulk the pkg requires |
| MacOSX10.9 SDK, stevedore, the compat guard, packaging, signing and release scripts | `Mavergreen/shipyard@v1` (`.github/actions/install`) | the github-actions manager tracks the tag | `@v1` moves without a pin changing here, so nothing repackages by itself |
| Sparkle, in the updater | shipyard's `fetch_sparkle_framework.sh`, pinned by hash there | ❌ untrackable here: shipyard owns that pin | follows shipyard |
| Takeover test inputs, CI only, never shipped: upstream macFUSE 4.0.5's dmg (`components/upstream-405/pin`) and osxfuse's SSHFS 2.5.0 installer (`components/sshfs-250/pin`), which `.github/workflows/on-mavericks.yml` Scenario C installs on the 10.9 guest before taking them over. sshfs: osxfuse's SSHFS 2.5.0 pkg is the brief's first preference, a pinnable upstream installer (ruled acceptable, task-11-report.md "Fix round 1"); no sshfs 2.10 installer is published, and building 2.10 in the job would need a 10.9 glib. Its binary links `/usr/local/lib/libosxfuse_i64.2.dylib` (one of the osxfuse compatibility links) and its receipt, `com.github.osxfuse.pkg.SSHFS`, must survive the takeover. No pinnable 10.9 installer carries upstream's own `io.macfuse.installer.components.sshfs` receipt, so `tests/vm/takeover-scenario.sh` builds a one-file marker pkg with that identifier and asserts it survives too. The 10.9 VM run by hand used the sshfs 2.10 binary its box already had, and SSHFS 2.5.0 extracted from the pinned pkg | each pin is one line, the download URL and its SHA-256 | nothing: both are fixed old releases, chosen as what a 10.9 user upgrading to this product has installed | by hand, only to test a different upstream install |

An upstream bump needs a person, and Renovate never automerges it (`.github/renovate.json`). Some goldens hold for one upstream release only, and `tests/lib/goldens-upstream` names it. These are `GOLDEN`, `GOLDEN_UNDEFINED` and `GOLDEN_RELOCS` in `tests/retarget-kext-test.sh` (the retargeted kext's sha256, its undefined symbols and its `_vnop_rename_desc` relocations) and the counts in `tests/lib/objc-measure.tsv` (the strict guard's excused findings). A new upstream fails them with "refresh for upstream X.Y.Z" and the measured values. To refresh, check the new kext: its undefined symbols must be 10.9's five KPIs plus Recaulk's back-fill, with no `_vnop_renamex_desc`. Then copy the printed values into those two files and write the new version to `tests/lib/goldens-upstream`, on the Renovate branch.

Upstream's release notes: `build/upstream-release-notes-url.sh` links `https://github.com/macfuse/macfuse/releases/tag/macfuse-<version>`.

## Conformance deviations

- macos-runner:release.yml:build: reading upstream's APFS dmg (build/extract-dmg.sh) needs hdiutil, and the strict compat guard (build/compat-guard.sh) runs only on macOS; exit: the dmg/APFS reader (shipyard QUEUE "A dmg/APFS reader that runs on 10.9 and Linux") and a Linux-hosted strict guard, after which the build runs on Linux.
- native-build:closed-helpers: a native 10.9 build cannot read the upstream dmg (APFS), so it lacks the closed helpers that ship only in the dmg. Exit: shipyard QUEUE "A dmg/APFS reader that runs on 10.9 and Linux".
- objc-measure:macFUSE: the strict compat guard (build/compat-guard.sh, Drydock v0.6.0) cannot measure macFUSE.framework for Drydock gaps only: its `_objc_loadWeak` import (a block-captured `__weak` under manual reference counting) is unclassified (unclassified-objc-runtime-import); clang copies `objc_msgSend` between registers in `fusefm_destroy` and tail-calls through the copy, which the reader does not follow (indirect-objc-entry); and once those are fixed, its load of upstream's absolute install name `/usr/local/lib/libfuse.2.dylib` is not resolvable inside a shipped root (escaping-dependency; not reported today, so it has no row yet). It passes the default guard; tests/lib/strict-measure.sh requires exactly the findings and counts tests/lib/objc-measure.tsv lists for it, so a gap that closes or appears forces the rows to change. Exit: the Drydock fixes (classify `_objc_loadWeak`, follow entry-point register copies, map absolute install names into the shipped root) pinned by shipyard; then delete its rows and this entry.
- objc-measure:libfuse.2.dylib: the strict compat guard cannot measure libfuse 2 for one Drydock gap only: its load of upstream's absolute install name `/Library/Filesystems/macfuse.fs/Contents/Frameworks/MFMount.framework/Versions/A/MFMount` is not resolvable inside a shipped root (escaping-dependency).
